# AI-200 Preparation Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate and ship `packs/azure-ai-200.json` in two releases:

- **1.0.0 "learn and practise":** practice pool of 150 questions, audited Nov 1 lessons, starter cards.
- **1.1.0 "complete":** adds five fixed 50-question papers, the full lesson set and 150+ cards.

Every fact is grounded in Microsoft Learn pages read through the MS Learn MCP tools.

**Architecture:**

- A Python generator in the gitignored `references/azure/ai-200/_build/` is ported from `references/safe/_build/common.py` and extended for case studies, `dropdown`, `numeric` and Yes/No grids.
- Content modules register questions per study-guide skill, lessons and flashcards.
- `build.py` emits a schemaVersion 1 hybrid pack (draft first). The CLI, blind reviewers and an isolated API walkthrough gate each release.
- The `ai-200` branch carries only the pack JSON, Makefile/README lines and docs.

**Tech Stack:**

- Python 3 (stdlib; `unittest` for builder tests).
- `references/azure/ai-200/.venv`, which has azure SDKs, psycopg, pgvector, redis, redisvl and opentelemetry, for code checks.
- LearnForge CLI (`tools/cli`), ASP.NET API, Angular web.
- MS Learn MCP: `microsoft_docs_search`, `microsoft_docs_fetch`, `microsoft_code_sample_search`.

**Spec:** `docs/superpowers/specs/2026-11-23-azure-ai-200-pack-design.md`

## Global Constraints

- Pack ID `azure-ai-200`; licence `CC0-1.0`. The description, `sources` and `start-here` lesson say the pack is independent and not Microsoft material.
- Objective IDs:
  - domains `ai200.containers`, `ai200.data`, `ai200.connect`, `ai200.secure`;
  - skills `<domain id>.<short>` (27 shorts, listed in Task 2);
  - prerequisites as in the 1 Nov spec.
- Question IDs are `<short>-NN`, positional per skill: practice questions first, then paper questions. **Append only**; after a release, never reorder, delete or change a practice count. One family per question (`familyId == id`).
- Domain weights 9/11/9/9 (midpoints 22.5/27.5/22.5/22.5 from the live en-US study guide). Recheck the live page at Task 2 and at each release task.
- Sizes:
  - practice pool 150, split 36/43/36/35 by `largest_remainder`;
  - paper questions 250, split 60/70/60/60;
  - per skill, at least 4 practice, at least 6 paper and at least 10 in total.
- Papers: 5 × 50 questions, 100 minutes, `passPoints` 35, each holding exactly one complete 5-question case study, domain mix 12/14/12/12, `requiredKinds ["single", "multiple", "matching"]`, `reserveFixedPapers: true`.
- Short mock: 20 questions, 40 minutes, weighted, `requiredKinds ["single"]`.
- 1.0.0 only: a generated full mock of 50 questions, 100 minutes, weighted, `requiredKinds ["single", "multiple"]`. It is removed in 1.1.0.
- Readiness in both releases: `{"shortAttempts": 0, "fullAttempts": 3, "threshold": 80, "lookbackDays": 90, "minimumFreshPercent": 100}`.
- Format mix ±5 points: single 55%, multiple 15%, dropdown 10%, matching including Yes/No grids 10%, sequence 6%, numeric 4%.
- Cognitive mix about 20/50/30 recall/apply/analyse (`lvl` `r`/`a`/`n`).
- Every question, card and fact-bearing lesson block cites at least one `SOURCE_KEYS` key. Every key has a saved MS Learn or SDK extract in `_build/text/<key>.md`. Nothing is copied verbatim from MS Learn, and Microsoft's practice assessment is never used.
- Questions test generally available features. A preview feature appears only where the skill bullet needs it and MS Learn treats it as commonly used, and its explanation says "preview".
- Prompts are one line. Code in a question goes in dropdown slot text or matching items, never multi-line prompts. Lesson text contains no raw URLs, and code lines are at most 88 characters.
- **The owner never sees question text.** All builder runs go through `_build/run.sh`, and reports to the owner give counts and IDs only.
- Build with `--draft` (writes `build/draft/azure-ai-200.json`). Write to `packs/` only when `lsof -nP -iTCP:4300 -iTCP:5080 -sTCP:LISTEN` prints nothing.
- Isolated verification only: API on 5091 and web on 4311, with scratch `ConnectionStrings__Database` and `DataProtection__KeyDirectory` in the scratchpad, never the launcher and never `apps/api/data`.
- The owner studies on `.learnforge/data/ai-200` (`bash scripts/install.sh --no-install --data-dir .learnforge/data/ai-200`).
- No engine changes on `ai-200`. Ask the owner before every commit and never push.
- Dates:
  - 1.0.0 by Thu 26 Nov.
  - 1.1.0 by Mon 30 Nov. It may slip to Wed 2 Dec; never cut papers or checks to hold a date.
  - Freeze after 1.1.0 (1.1.1 only for a wrong key or fact).

## Review Focus

1. **Upgrade in place (1.0.0 → 1.1.0 in one database):** lessons the learner opened show as revised, not reset. All five papers start fresh. Readiness restarts and says so. Tested in Task 9 step 5.
2. **Practice must never serve an unseen paper question:** short mocks and focused practice on 1.1.0 contain no paper question IDs until that paper is taken. Tested in Task 9 step 5.
3. **Numeric answers:** a learner types `400`, not `400 RU/s`. Every numeric prompt names its unit and ends with "Enter a number." A decimal key needs a tolerance. Tested in Task 1 (`test_num_prompt_and_tolerance`).
4. **Phone-width rendering:** code blocks, tables and case-study backgrounds stay readable at 390 px. Lesson text has no raw URLs, code lines are at most 88 characters, and tables have at most 4 columns. Tested in Task 1 (`test_lesson_layout_limits`) and by eye in Task 5 step 6.
5. **Yes/No grids as reusable matching:** they render, can be answered by keyboard, and give partial credit per statement. Tested in Task 5 step 6.

### Task 1: Port the builder library

**Files:**
- Snapshot first: copy `references/azure/ai-200/_build/` to `references/azure/ai-200/_build_nov1/`. This is read-only reference; nothing imports it.
- Replace: `references/azure/ai-200/_build/common.py` (start from `references/safe/_build/common.py`).
- Create: `references/azure/ai-200/_build/test_common.py`, `_build/run.sh` (copy of `references/istqb/_build/run.sh`), `_build/lintmod.py`, `_build/chk.py`.

**Interfaces:**
- Produces, in `common.py`:
  - Constants: `LICENSE = "CC0-1.0"` and `NOTICE`. `NOTICE` is one sentence saying the pack is independent and not affiliated with or endorsed by Microsoft.
  - Question helpers. Every one takes `(lvl, src, prompt, …, explanation, case=None)`, and `src` is a non-empty space-separated key string:
    - `S(lvl, src, prompt, key, distractors, explanation, case=None)`: exactly 3 distractors.
    - `M(lvl, src, prompt, keys, distractors, explanation, case=None)`: 2 or 3 keys, and "TWO"/"THREE" in the prompt.
    - `SEQ(lvl, src, prompt, steps, explanation, case=None)`: 3–8 steps.
    - `MATCH(lvl, src, prompt, pairs, extras, explanation, case=None)`: at least 3 pairs and at least 1 extra.
    - `YN(lvl, src, prompt, statements, explanation, case=None)`: statements are `[(text, bool)]`, 3–4 of them, with at least one True and one False. Emits a `matching` record with options `Yes` and `No` and `reuse: true`.
    - `DD(lvl, src, prompt, blanks, explanation, case=None)`: blanks are `[(slot_text, answer, distractors)]`, each with at least 2 distractors.
    - `NUM(lvl, src, prompt, answer, unit, explanation, tolerance=None, case=None)`: appends `f" Answer in {unit}. Enter a number."` to the prompt. A non-integer `answer` asserts a tolerance.
  - Lesson helpers: `L(id, title, summary, objectives, blocks)`. `T`, `CO`, `EX`, `CODE` and `TAB(title, …, src="")` keep `src` on the block dict under `"_src"`, which is stripped at build. `AUTO()`.
  - Card helpers: `CB`, `CR`, `CC(id, skill_id, …, explanation, tags, src)`. `src` is required and is turned into `sources: [{title, url}]`.
  - `Item = tuple[str, dict, str, str, str]`, meaning `(qid, q, domain_id, skill_id, pool)` with `pool` either `"practice"` or `"paper"`.
  - `collect(spec, practice: dict[str, list], papers: dict[str, list]) -> list[Item]`. Modules are keyed by skill short. Raises `SystemExit("ERRORS…")` listing IDs only, for:
    - count mismatches against `spec.SKILLS[*]["practice"]` and `["paper"]`;
    - an unknown skill, an unknown or missing source key, or an unknown `case`;
    - duplicate prompts;
    - a case study with fewer than 2 questions.
  - `make_papers(spec, items, scenarios) -> list[list[str]]`: places exactly one paper-pool scenario group per paper, then fills each paper to the domain quota `largest_remainder(50, weights)` minus that scenario's per-domain count, round-robin over skills in `_h("paper"+qid)` order. Asserts that every paper-pool question is used exactly once.
  - `build_full(spec, items, scenarios, lessons, cards, out_pack, out_map) -> int`: returns the local lint findings. `spec.WITH_PAPERS` selects the 1.0.0 or 1.1.0 blueprint set from Global Constraints. It appends a generated "Sources" text block (titles only) to each lesson, strips `_src`, and adds the domain objective in front of skill objectives on questions, lessons and cards.
  - `local_lint(items) -> int`:
    - the SAFe rules LF201, LF203, LF204, LF205 and LF211;
    - a port of LF209 for single, dropdown, matching (non-reuse) and sequence;
    - key-length rank counted as a finding when the key is longest in fewer than 10% or more than 25% of singles, or shortest in 40% or more.
  - `report(spec, items, cards, lessons)`: prints counts per domain, skill, kind and level only.
- `chk.py`: `python3 -I chk.py` prints per-skill practice, paper and card counts, the format and level mix against targets, and lint totals. `lintmod.py <module>` lints one content module.

- [ ] **Step 1: Write the failing tests in `test_common.py`** (stdlib `unittest`; a tiny fixture spec with 2 domains, 3 skills, 2 sources and `WITH_PAPERS` True):
  - `test_oid_matches_exam_source_adapter`: `oid("q1", "", "Text") == "o" + sha256("q1\x1f\x1fText")[:8]`.
  - `test_yn_is_reusable_matching`: kind `matching`, `reuse` True, option texts `{"Yes", "No"}`, one slot per statement, and `matches` maps each slot to the Yes or No option ID.
  - `test_dd_blank_has_three_choices`: a blank with 1 distractor raises `AssertionError`; with 2, the slot has 3 options.
  - `test_num_prompt_and_tolerance`: the prompt ends with "Enter a number."; `NUM(…, answer=2.5, tolerance=None)` raises; grading `correct == ["400"]` for `answer=400`.
  - `test_uncited_item_rejected`: `src=""` raises, and an unknown key makes `collect` exit with the item's ID in the message and no prompt text.
  - `test_ids_positional_practice_then_paper`: with 2 practice and 3 paper questions for skill `acr`, the IDs are `acr-01` through `acr-05` in that order.
  - `test_papers_disjoint_complete_and_weighted`: a fixture with 2 papers of 10, 2 scenarios of 3 and a quota of 4/6. Papers are disjoint, each holds exactly one whole scenario, domain counts match the quota, and the union equals the paper pool.
  - `test_blueprints_by_stage`: with `WITH_PAPERS` False the blueprints are `short` and `full`, with no `questionIds` and no `reserveFixedPapers`. With True they are `short` and `paper-a`, `paper-b`, each with `passPoints == ceil(0.7 * count)` and `reserveFixedPapers` True.
  - `test_lesson_layout_limits`: a lesson block containing `https://` raises; a code line of 89 characters raises; a table with 5 columns raises.
